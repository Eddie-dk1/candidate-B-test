# Тестовое задание: аванс по договору

Около 2-3 часов. Работа - в Claude Code.

## Контекст

Компания заказывает работы у подрядчиков: съёмки, дизайн. Договор с подрядчиком - это общая сумма на несколько работ. Платим по договору авансом и остатками, иногда платёж привязан к конкретной работе.

Письмо бухгалтера:

> Мне нужен отчёт: по каждой работе - сколько уже выплачено и сколько осталось оплатить, и итог по каждому договору. Сейчас считаю в таблице руками и путаюсь: платежи по договору ни к какой работе не привязаны, а мне надо понимать, за что мы уже рассчитались. Отчёт нужен на дату, для проверки - на 10.11.2026.

## Что есть

Папка `data/`: договоры, работы, платежи и описание формата в `FORMAT.md`.

Бухгалтер в отпуске и на связи не будет, других источников, кроме `data/`, нет. Где данных не хватает, решите сами и запишите допущение в `DECISIONS.md`.

## Что сдать

1. **Программа** на Python или TypeScript - скрипт, CLI или маленький HTTP-сервис, на ваш выбор. По файлам из `data/` и дате она строит отчёт:
   - по каждой работе: цена, выплачено, осталось оплатить;
   - по каждому договору: итоги.

   Напишите, как её запустить: мы запустим сами.

2. **Файл `DECISIONS.md`** - решения, которые вы приняли по ходу работы. По каждому решению коротко:
   - что решали;
   - какие были варианты;
   - что выбрали и почему;
   - что изменится в отчёте, если выбор окажется неверным.

   Пример оформления на постороннюю тему:

   > **Формат отчёта.** Варианты: таблица в консоли или файл CSV. Выбрал CSV: его можно открыть в таблице. Если неверно, поменяется только вывод, расчёт останется прежним.

3. **Записка бухгалтеру** на 5-10 строк простым языком: как читать отчёт и что ей нужно подтвердить, когда вернётся.

4. **Полный транскрипт работы с Claude Code** - экспорт командой `/export`, без правок. Если сессий было несколько - все. Ключи и пароли, если попали в сессию, можно вырезать.

Интерфейс, база данных и docker не нужны. Деньги считайте точно, до копейки, без float.

Не успели всё - напишите, что осталось и что бы вы сделали дальше.

# Готовое решение

Программа строит воспроизводимый снимок на дату. Денежные операции выполняются
целыми копейками, без float и округления. Требуется **Python 3.11 или новее**;
дополнительные пакеты и установка проекта не нужны.

## Запуск

Из корня проекта:

```bash
python3 -m advance_report --data-dir data --as-of 2026-11-10 --output-dir reports/2026-11-10
```

Произвольная дата и справка:

```bash
python3 -m advance_report --data-dir data --as-of 2026-11-12 --output-dir reports/2026-11-12
python3 -m advance_report --help
```

Дата обязательна, формат — `YYYY-MM-DD`; учитываются события до конца этого дня.
`--data-dir` по умолчанию равен `data`, `--output-dir` обязателен. Пути считаются
от текущего рабочего каталога. Допускаются абсолютные пути и пути с пробелами
(заключайте их в кавычки).

В каталоге результатов создаются три CSV. При повторном запуске они заменяются,
другие файлы не удаляются. Для истории используйте отдельный каталог для каждой
даты; для параллельных запусков — разные каталоги. Писать поверх входных CSV
программа запрещает. Исходная выгрузка не изменяется.

Коды завершения: `0` — успех, `1` — ошибка входных данных или записи,
`2` — неверные аргументы. Ошибки данных содержат файл, строку и причину.
Вся выгрузка проверяется до записи; при ошибке данных прежние результаты
сохраняются. Замена каждого CSV атомарна, но весь комплект из трёх файлов
не является транзакцией: после сбоя записи повторите команду.

## Как читать файлы

Формат: CSV с запятой, UTF-8 BOM, десятичная точка, два знака после точки.
В Excel при необходимости используйте импорт «Из текста/CSV», кодировку UTF-8
и разделитель «запятая». Все денежные значения в отчётах — **рубли**;
только внутри программы они хранятся в копейках.

### works.csv — по работам

| Колонка | Значение |
|---|---|
| `as_of`, `contract_id`, `work_id`, `title` | Дата снимка, договор, работа, название. |
| `status_as_of` | Состояние именно на дату: planned, done или cancelled. |
| `price` | Исходная цена, в том числе у отменённой работы. |
| `obligation` | Цена действующей работы; у отменённой — ноль. |
| `direct_paid` | Адресные платежи за вычетом возвратов на эту дату. |
| `allocated_advance` | Расчётная доля общего аванса. |
| `paid` | Сумма direct_paid и allocated_advance. |
| `remaining` | Непокрытое обязательство, минимум ноль. |
| `overpayment` | Оплата сверх obligation; остаётся за адресной работой. |

### contracts.csv — по договорам

| Колонка | Значение |
|---|---|
| `as_of`, `contract_id`, `contractor` | Дата, договор, подрядчик. |
| `contract_amount` | Номинальная сумма договора из выгрузки. |
| `works_price` | Сумма исходных цен всех перечисленных работ. |
| `active_works_price` | Сумма obligation работ, без отменённых. |
| `gross_paid`, `refunded` | Фактически отправлено и фактически возвращено к дате. |
| `net_paid` | gross_paid − refunded. |
| `allocated_paid` | Сумма paid всех работ, включая адресные переплаты. |
| `unallocated_advance` | Общий аванс, которому не хватило доступной стоимости работ. |
| `remaining` | Сумма remaining работ, а не разность суммы договора и оплаты. |
| `accepted_remaining` | Непокрытая стоимость принятых работ; не утверждение о просрочке. |
| `nominal_balance` | contract_amount − net_paid; может быть отрицательным. |

Контроль баланса: `net_paid = allocated_paid + unallocated_advance`.
Адресная переплата не уменьшает остаток другой работы.

### diagnostics.csv — пояснения и вопросы для сверки

Колонки: `as_of`, `code`, `entity_type`, `entity_id`, `message`.
Общие допущения выводятся всегда. Диагностика не означает ошибку запуска:
расчёт выполнен, но некоторые выводы требуют подтверждения.

| Код | Что проверить |
|---|---|
| `ALLOCATION_POLICY` | Условный порядок распределения общих платежей. |
| `HISTORICAL_WORK_LIST` | Все работы известны с подписания, цены считаются неизменными. |
| `BALANCE_NOT_DUE` | Остаток стоимости не устанавливает срок платежа. |
| `QUEUED_PAYMENT` | Платёж в очереди исключён из фактической оплаты. |
| `CANCELLED_WORK`, `CANCELLATION_BALANCE` | Отмена обнуляет обязательство работы, но не меняет сумму договора. |
| `WORKS_CONTRACT_MISMATCH` | Исходная сумма цен работ отличается от суммы договора. |
| `WORK_OVERPAYMENT`, `CANCELLED_WORK_PAID` | Адресная переплата требует отдельного решения. |
| `UNALLOCATED_ADVANCE` | Общая оплата сверх доступной стоимости работ. |
| `CONTRACT_OVERPAYMENT` | Чистая оплата превышает номинальную сумму договора. |

## Контрольный результат на 10.11.2026

Пример уже сохранён в `reports/2026-11-10/`.

| Договор | Отправлено | Возвращено | Чистая оплата | Остаток по действующим работам | Остаток принятых работ | Номинальный остаток договора |
|---|---:|---:|---:|---:|---:|---:|
| D-1 | 365 000,00 | 50 000,00 | 315 000,00 | 185 000,00 | 0,00 | 285 000,00 |
| D-2 | 75 000,00 | 0,00 | 75 000,00 | 15 000,00 | 0,00 | 15 000,00 |

По D-1 отменена W-13 стоимостью 100 000,00, поэтому номинальный остаток
договора отличается от остатка действующих работ. Платёж P-3 на материалы
включён в оплату W-14. Нераспределённого аванса на эту дату нет.

| Работа | Состояние | Оплачено расчётно | Осталось |
|---|---|---:|---:|
| W-11 | done | 100 000,00 | 0,00 |
| W-12 | done | 100 000,00 | 0,00 |
| W-13 | cancelled | 0,00 | 0,00 |
| W-14 | done | 100 000,00 | 0,00 |
| W-15 | planned | 15 000,00 | 85 000,00 |
| W-16 | planned | 0,00 | 100 000,00 |
| W-21 | done | 20 000,00 | 0,00 |
| W-22 | done | 30 000,00 | 0,00 |
| W-23 | planned | 25 000,00 | 15 000,00 |

W-23 принята только 11 ноября, а P-8 оплачен 12 ноября — на контрольную дату
эти события не действуют. На 11 ноября у D-2 появится `accepted_remaining`
15 000,00; на 12 ноября он обнулится, но останется нераспределённый аванс
5 000,00 и `nominal_balance` −5 000,00.

## Проверки

```bash
python3 -m unittest discover -s tests -v
```

Тесты покрывают контрольный пример, границы дат, очередь и возвраты,
исторические состояния, адресные платежи, отмены, переплаты, копейки и большие
суммы, пустые таблицы, изоляцию договоров, ошибки CSV и ссылок, защиту источников,
CLI и повторяемость результатов. Дополнительно проверяются 100 воспроизводимых
случайных наборов на сохранение денежных сумм и отсутствие изменения входа.

## Устройство и документы

- `advance_report/models.py` — неизменяемые модели; денежные поля — копейки.
- `advance_report/input.py` — разбор CSV, денег и дат, проверка связей и хронологии.
- `advance_report/report.py` — чистый расчёт без записи и внешних сервисов.
- `advance_report/cli.py` — аргументы, CSV и обработка ошибок.
- `tests/test_advance_report.py` — автоматические проверки на unittest.
- `DECISIONS.md` — варианты, принятые решения и последствия неверных допущений.
- `ACCOUNTANT_NOTE.md` — записка бухгалтеру на 9 строк.

Функция `build_report(data, as_of)` принимает набор, проверенный `load_dataset`,
и возвращает неизменяемый `Report`. Даты и суммы не зависят от локали компьютера.
Фактическую привязку общего аванса к работам из этих данных восстановить нельзя:
она заменена явно описанным расчётным правилом. История изменений цен и состава
работ, частичные возвраты и сроки обязательной оплаты в данных отсутствуют.
